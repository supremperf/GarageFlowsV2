--------------------------------------------------------------------------------
5. CE QUI RESTE NON JOUE, ET POURQUOI
--------------------------------------------------------------------------------

  Non execute : installation, raccourcis, entree de desinstallation, mise a
  niveau, desinstallation, activation et HWID sur poste vierge.

  Raison : ce poste heberge une installation REELLE de GarageFlows et les
  donnees metier de l'utilisateur. L'`appId` etant partage, une installation de
  test rendrait l'installation existante non desinstallable. La procedure
  officielle du projet refuse d'ailleurs de s'executer ici.

  Je ne peux pas creer de machine virtuelle Windows jetable depuis cette
  session : c'est un prerequis materiel externe.

  Procedure a executer sur une machine Windows propre :

    Get-FileHash .\GarageFlows-Setup.exe -Algorithm SHA256   # avant d'executer
    $env:GITHUB_ACTIONS = "true"
    $env:RUNNER_OS = "Windows"
    $env:GF_WINDOWS_SMOKE_ISOLATED = "1"
    powershell -NoProfile -ExecutionPolicy Bypass -File scripts\test-windows-setup.ps1

  Puis, avec une licence de test : activation, HWID, creation d'un client et
  d'une facture, export PDF, parametres, comportement hors ligne, mise a niveau
  depuis la version precedente, desinstallation avec verification que les
  donnees survivent.

  Preuve attendue : le JSON de resultat avec `success: true`.

--------------------------------------------------------------------------------
6. OBTENIR UN CERTIFICAT — PROCEDURE
--------------------------------------------------------------------------------

  Deux options, selon le besoin de reputation immediate :

    OV  (validation d'organisation) — moins couteux. La reputation SmartScreen
        se construit avec le volume de telechargements : les premiers clients
        verront encore un avertissement.
    EV  (validation etendue) — cle en HSM ou jeton materiel, reputation
        SmartScreen immediate. Plus couteux, et impose une signature depuis une
        machine ayant acces au materiel, donc une CI adaptee.

  Mise en oeuvre, une fois le certificat obtenu :

    - ne JAMAIS committer le certificat ni son mot de passe ;
    - fournir `CSC_LINK` (chemin ou base64 du .pfx) et `CSC_KEY_PASSWORD` par
      les secrets de la CI, jamais dans `package.json` ;
    - reconstruire : `npm run dist` signera alors l'installateur et les
      executables ;
    - verifier : `Get-AuthenticodeSignature` doit renvoyer `Status: Valid`, et
      le recu de livraison doit porter `authenticodeVerified: true`.
